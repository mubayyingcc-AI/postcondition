Did the agent's action actually happen?

An agent can report success while the system of record says otherwise. A Postcondition receipt records what the system actually confirmed, and is signed so nobody can quietly edit it. The receipt below is real. Verify it, then change one field and verify again.

Press Verify receipt to check the signature.

Seven outcomes, and one of them is "we don't know"

  • EXECUTED_AND_VERIFIED The system confirmed the expected result.
  • EXECUTED_BUT_POSTCONDITION_FAILED The action was submitted but the expected result did not hold.
  • COMPENSATION_REQUIRED Something partly applied and needs a corrective step.
  • CONFLICT_DETECTED Another writer changed the target in between.
  • REJECTED_BY_POLICY Never submitted; a check failed first.
  • ALLOWED_NOT_EXECUTED Permitted, but never submitted.
  • UNKNOWN_OUTCOME Submitted, but the result could not be established yet. Never reported as success or failure.

First connector: refunds on Paystack, in test mode.

What a receipt says

That a specific policy was evaluated before the action, that the request was submitted, and what the system of record reported afterwards. Every receipt lists exactly what it asserts.

What it does not say

  • That the AI reasoned correctly.
  • That the policy itself was a good one.
  • That nothing else happened outside what was observed.
  • That a signature check today means the fact is still true today.

Verify from code

curl -X POST /v1/verify \
  -H "Content-Type: application/json" \
  -d '{"receipt": {...}, "public_key": "base64..."}'

Signing keys this server uses are listed at /v1/keys. The verifier is open source, so you can check receipts without trusting this site.

Postcondition is early. It has one connector and it has only been run against Paystack's test mode.
